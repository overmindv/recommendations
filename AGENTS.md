# recommendations: инструкции агента

Stateless Go/parker сервис подбора практики. Публичный контракт обслуживает gateway;
внутренний endpoint принимает только service token и проверенный actor. Читать
`README.md` перед изменением политики и `../docs/openspec/changes/recommendations-mvp/`.

- Не вводить mastery/completion без независимой проверки; пороги — версионированная эвристика.
- Не читать чужие БД и не принимать код, скрытые тесты, ответы или actor из body.
- Сначала завершить функциональный срез, затем тесты (правило локального backlog).
- `tasks.md` — отдельный проектный backlog; не отмечать его целиком выполненным.
- Комментарии/документация на русском, идентификаторы/API/ошибки на английском.
- Проверки: `make lint`, `make test`, `make build`, `make benchmark`.

## Общий agent harness

Для изменения поведения прочитай `../docs/harness/README.md` и релевантную
спецификацию в `../docs/openspec/`. Это sibling-репозиторий `overmindv/docs`,
а не каталог документации этого сервиса. При отдельном checkout и отсутствии
соседа используй локальные правила; нехватку сквозного контекста укажи явно.

- Перед работой зафиксируй `git status --short`; сохраняй чужие незавершённые изменения.
- Работай одним проверяемым срезом; рутинные обратимые решения принимай самостоятельно.
- На смену контракта найди производителей/потребителей и проверь их совместимость.
- Пользовательские сценарии студента и автора/модератора имеют равный приоритет.
- Проверки: `make -C ../infra agent-verify SERVICE=recommendations DRY_RUN=1` показывает команды.
- В конце приведи фактические результаты и непроверенные места; сохрани следующий шаг.
- Не публикуй, не очищай БД и не отправляй изменения автоматически.
