# Версии учебного плана

Recommendations хранит текущую версию и предыдущие снимки по каждой цели.
Снимок содержит календарь, версии ресурсов, обе политики и их веса.
`evidence_watermark` хранит SHA-256 учтенных независимых оценок, их исправлений
и политики расчета. Это отпечаток входных данных, не Kafka offset.

При генерации сервер берет цель, бюджет и граф из собственной БД. На каждую
тему он рассматривает до десяти версий задач и десяти материалов из проекции.
Tasks и Content пакетами подтверждают конкретные версии. Для контрольной
задачи Tasks также проверяет, что пользователь раньше ее не решал.
Недавние решения, уже решенные задачи и прочитанные версии материалов
не рекомендуются повторно. Активная повторная проверка сохраняет закрепленную
версию задачи. Если владелец ее отозвал, новой задачей ее не подменяем.

Сохранение версии, текущего указателя, шагов и ключа запроса идет в одной
транзакции. После расчета сервер повторно проверяет версии и минуты, отведенные
другим целям. При конфликте текущий план не меняется. Повтор ключа возвращает
исходную версию без обращения к каталогам; прогресс по ней читается заново.
Ключи хранятся вместе с версиями плана. Предел: 1024 версии на цель.

## Внутренний API

Все маршруты требуют Bearer-токен и доверенный `X-User-ID`. План доступен
только владельцу цели. Выполнение шагов в старой версии запрещено.

| Метод | Маршрут относительно `/v1/learner/goals/{id}/study-plan` | Тело |
| --- | --- | --- |
| GET | Корень | Без тела |
| GET | `/explanation?plan_version=N` | Без тела |
| PUT | Корень | `goal_version`, `availability_version`, `plan_version` |
| PUT | `/steps/{ordinal}/start` | `plan_version` |
| PUT | `/steps/{ordinal}/activity` | `plan_version` |
| PUT | `/steps/{ordinal}/assessment` | `plan_version` |

Для генерации нужен UUID в `Idempotency-Key`. Первая версия создается с
`plan_version: 0`. GET возвращает сохраненную версию без перерасчета плана.
Если цель или бюджет поменялись, план остается доступен с `stale: true` и
без следующего шага; новую версию нужно запросить явно.

`next_step` содержит номер доступного шага. Для темы с условием допуска
нужна независимая проверка предпосылки и достаточный балл по ее политике.
Отметка выполнения теории или практики не влияет на `goal_demonstrated`.
Для контрольной задачи сервер сам проверяет независимую оценку пользователя
по закрепленной версии, а при ее отсутствии возвращает `GRADE_PENDING`.
После исправления результата прежнее подтверждение больше не действует.

Начало шага можно записать отдельно через `/start`. Сохраненный
`activity_started_at` не означает, что шаг выполнен или знания подтверждены.

Сбой каталога возвращает 503 при генерации и не меняет сохраненный план.
Ответы не содержат код решений, скрытые тесты или идентификаторы событий оценки.

## Включение

По умолчанию выключено. Для `RECOMMENDATIONS_STUDY_PLANS_ENABLED=true` нужны
PostgreSQL с миграциями до `202611190018`, проекция каталога, учебные события
и политика оценки знаний.

- `RECOMMENDATIONS_STUDY_RANKING_POLICY`: JSON политики ранжирования. Поля:
  `policy_version`, `target_bps`, `unknown_gap_bps`, `prerequisite_min_bps`,
  `medium_difficulty_bps`, `hard_difficulty_bps` и объект `weights`.
- `RECOMMENDATIONS_STUDY_RECENT_WINDOW`: интервал от `1h` до `720h`, целыми секундами.

Порогов пилота по умолчанию нет. Связка с публичным GraphQL описывается отдельно.

## Адаптация

При `RECOMMENDATIONS_STUDY_ADAPTATION_ENABLED=true` независимая оценка
обновляет снимок знаний и ставит пересчет плана в очередь в одной транзакции.
Серия оценок объединяется в одну запись на цель. Задайте
`RECOMMENDATIONS_STUDY_ADAPTATION_WINDOW` от `1s` до `5m`, целыми секундами.
Серия не откладывает пересчет дольше четырех таких интервалов. Повторные
попытки по одной задаче не меняют первую независимую оценку.

Воркер сохраняет начатые и завершенные шаги и меняет только оставшуюся часть.
После проваленной проверки возможен дополнительный материал и новая контрольная
задача. Прежняя проверка остается с `superseded: true`. Если нужного материала,
новой задачи или времени нет, причина остается в `unmet_outcomes`.
При достаточной независимой оценке лишние незапущенные шаги исключаются.
Если шаги и результаты плана не изменились, новая версия не сохраняется.
Сбой каталога оставляет текущую версию и переносит пересчет.

## Объяснения

`GET /explanation?plan_version=N` возвращает причины по номеру шага
и ограничения плана: недостающий ресурс, время, базовую тему или лимит шагов.
Если версия сменилась, вернется `VERSION_CONFLICT`. Шаблоны объяснений
не используют LLM, тексты решений или идентификаторы сдач.

`evidence` содержит сводку независимых оценок по теме: размер выборки,
последнюю учтенную оценку по времени, неопределенность и балл, если он есть.
`evidence.ref` связывает сводку с политикой и отпечатком данных, по которым
выбран шаг. У перенесенного шага остается исходная сводка.
Для старого плана без нее возвращается `not_recorded`, не нулевой балл.

Запасной ресурс есть только у следующего неначатого шага теории или
практики. Он помещается в ту же неделю и не дублирует шаги плана.
Это ресурс из подтвержденного при расчете каталога, а не замена шага
или право доступа к отозванному материалу. Контрольные задачи не раскрывают
запасные варианты, чтобы не нарушить независимость проверки.

## Проверка

Тесты используют отдельные PostgreSQL базы `_test` с миграциями.
`STUDY_PLANS_TEST_DSN` подходит для хранилища, `DIAGNOSTIC_TEST_DSN` для HTTP
и `RESOURCE_PROJECTION_TEST_DSN` для замера локальной выборки.
Для тестов расписания и консьюмера задавайте разные базы в
`STUDY_PLANS_TEST_DSN` и `LEARNING_EVIDENCE_TEST_DSN`.
HTTP-тест поднимает тестовые Tasks по HTTP и Content по gRPC.

```bash
go test -race ./internal/studyplans ./internal/httpapi
go test ./internal/studyplans -run '^$' -bench BenchmarkCurrentStudyPlan -benchmem
go test ./internal/projection/resources -run '^$' -bench BenchmarkStudyCandidateRead -benchmem
```
