# Подтверждение учебной цели

Recommendations публикует `goal.completed` и `goal.reopened` в
`learning.goal.v1`. Это закрытый поток для Rating, не события ленты.
Ключ Kafka - `goal_id`. Формат определен в `pkg/api/goalcompletion`.

## Что считается подтверждением

Решение принимает сервис по сохраненному плану. Балл по каждой целевой теме
и обязательной предпосылке должен пройти порог политики плана на достаточной
выборке независимых оценок. Для каждой назначенной контрольной задачи нужна
первая независимая сдача с `accepted`, по той же версии и теме, не раньше
назначения. Самооценка, прохождение материала, пропуск и пробный запуск
не подтверждают цель.

При первом подтверждении сохраняется версия плана, на которой выполнены
условия. Пересчет расписания, пауза и смена бюджета ее не меняют. Если
исправление оценки лишает цель подтверждения, приходит `goal.reopened`.
Смена целевых тем, деактивация или удаление цели также снимают подтверждение.
Если после отзыва актуальный план уже подтвержден, следом может прийти
`goal.completed` с новым номером.

Итог работы, изменения цели и сохранение плана ставят проверку в очередь
в той же транзакции. Проверка не обращается в Tasks, Content или Entities.
Изменение состояния и запись в outbox также атомарны.

Восстановление оценок также ставит затронутые цели на проверку. Если публикация
выключена, в очередь попадают только пользователи с уже подтвержденными целями.

## Доставка

- `event_id` сохраняется в outbox и не меняется при повторной отправке.
- `aggregate_id` равен ID цели. `aggregate_version` и `completion_version`
  совпадают и растут только при изменении состояния, начиная с 1.
- `business_award_key` равен `learning_goal:<goal_id>` для всех событий цели.
  Потребитель хранит одну награду по этому ключу и версию последнего примененного
  состояния. Повтор или более старая версия не меняют баланс. `goal.reopened`
  снимает начисление, а повторное подтверждение восстанавливает, не удваивает его.
- В payload есть ID ученика, целевых тем и версии основания. Кода, ответов,
  ID сдач, логов и персональных профилей нет. `occurred_at` не задает порядок.

Доставка at-least-once. После ошибки воркер повторяет ту же запись. Пока не
получено подтверждение старой версии, новая версия той же цели не отправляется.
После потери ответа брокера потребитель должен выдержать повтор.

## Включение

Сначала применить миграции до `202611220005` и создать `learning.goal.v1`
на стороне infra. Учетной записи Recommendations нужны права записи в топик.
`RECOMMENDATIONS_GOAL_COMPLETION_ENABLED=true` требует включенных учебных планов
и приема учебных событий. Автоматическая адаптация расписания не обязательна.
Режим выключен по умолчанию. История не ставится на пересчет при включении:
проверка запускается на следующем событии или изменении плана.

Проверка начисления в Rating относится к OVM-190. Здесь тестируются расчет,
отзыв, откат транзакции и доставка события тестовому Kafka-потребителю.

## Проверка

Для тестов нужны отдельные базы PostgreSQL `_test` с миграциями.
В локальном Kafka создать `learning.goal.v1` с одним разделом.

```bash
go test ./internal/consumer -run TestPostgresGoalCompletion
go test ./internal/outbox -run TestPostgresGoalOutbox
go test ./internal/consumer -run '^$' -bench BenchmarkPostgresGoalCompletion
```

`LEARNING_EVIDENCE_TEST_DSN` нужен для приема итогов и проверки достижения,
`GOAL_OUTBOX_TEST_DSN` для publisher, `GOAL_COMPLETION_KAFKA_TEST_BROKER`
для доставки в локальный брокер.
