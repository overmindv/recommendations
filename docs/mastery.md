# Начальная оценка знаний

Оценка строится отдельно для каждой темы сохраненной учебной цели. В расчет
попадает первая независимая оцененная сдача задачи, даже если у задачи есть
несколько версий. При одинаковом времени сдачи выбирается меньший UUID сдачи.
Повторы, самооценка, чтение материалов и технические ошибки баллов не добавляют.

У каждой задачи общий вес 1 000 000 долей. Если у задачи несколько тем, вес
делится по пропорции из каталога для той же версии задачи. При отсутствии
таких данных темы получают равные доли. Остаток от округления распределяется
по одной доле в порядке UUID тем. Вес сохраняется вместе с оценкой и при
исправлении вердикта не пересчитывается по текущему каталогу.

Балл темы равен доле веса принятых сдач среди веса всех зачтенных сдач.
`score_bps` хранится целым числом от 0 до 10000 со стандартным округлением.
Ноль означает, что сдачи были, но ни одна не принята. `null` и `unknown`
означают, что в расчет не попала ни одна сдача по теме.

Снимок содержит число задач, суммарный вес, время последней оценки и причину
неопределенности. При весе ниже порога можно видеть балл, но вывод по теме
остается `insufficient`. Сервис рассматривает не более 512 последних
независимых сдач, исключая повторы даже при первой сдаче за пределами окна.
При обрезанной истории `truncated=true` и `uncertainty=bounded_history`.
Хороший балл на такой выборке не считается подтверждением знаний.

## API

Внутренний маршрут: `/v1/learner/goals/{id}/mastery`. Нужны Bearer-токен gateway
и заголовок `X-User-ID` с идентификатором владельца цели.

- `PUT` с телом `{"goal_version":1}` пересчитывает и сохраняет снимок.
  Несовпадение версии цели возвращает 409.
- `GET` возвращает сохраненный снимок для текущих версий цели и правил.
  Если снимка нет или цель принадлежит другому пользователю, ответ 404.

PostgreSQL хранит один текущий снимок по цели с версией правил и входными
оценками, которые реально участвовали в расчете. Исправление оценки становится
видно после следующего `PUT`. Идентификаторы событий и сдач не входят в HTTP-ответ.

## Настройки

Миграции до `202611190009` нужно применить до запуска новой версии сервиса:
прием учебных событий записывает веса и при выключенном расчете.

`RECOMMENDATIONS_MASTERY_ENABLED` по умолчанию выключен. Для включения нужна
настройка всех четырех параметров:

| Переменная | Назначение |
| --- | --- |
| `RECOMMENDATIONS_MASTERY_POLICY_REVISION` | Уникальная версия правил |
| `RECOMMENDATIONS_MASTERY_GAP_MAX_BPS` | Верхний порог состояния `gap` |
| `RECOMMENDATIONS_MASTERY_DEMONSTRATED_MIN_BPS` | Нижний порог `demonstrated_in_sample` |
| `RECOMMENDATIONS_MASTERY_MIN_WEIGHTED_TASKS` | Минимальное количество задач по весу |

Пороги задаются после согласования. При смене порога нужна новая версия правил.
Сервис не запускается, если под указанной версией уже сохранены другие параметры.

## Проверка

Запускать с отдельной базой `_test` в `MASTERY_TEST_DSN` и такой же отдельной базой
для тестов приема Kafka-событий в `LEARNING_EVIDENCE_TEST_DSN`. Применить
миграции перед тестами.

```bash
go test -race ./internal/mastery ./internal/httpapi ./internal/consumer
go test ./internal/mastery -run '^$' -bench BenchmarkMasteryEvidenceWindow -benchmem
```

Бенчмарк читает окно по одному пользователю с 50 000 сдачами. Записи создаются
во временной таблице с теми же индексами. Перед замером выполняется `ANALYZE`.
