# Прием учебных событий

Recommendations читает два отдельных потока:

| Топик | Владелец | Что сохраняется |
| --- | --- | --- |
| `learning.outcome.v1` | Tasks | Оцененный результат, версия и темы задачи, время, признак независимой попытки |
| `content.learning.v1` | Content | Подтверждение чтения конкретной редакции, только `self_reported` |

В исходном событии Content нет темы. Приемник не подставляет тему из более
новой версии материала. Чтение не считается подтверждением навыка.
Пробные запуски, ошибки инфраструктуры и некорректные события не попадают в
оцененную историю.

Inbox дедуплицирует события по источнику и `event_id`. Другой payload с тем же
ID отклоняется. Для решения сохраняется
наибольшая `correction_version`; исправление не меняет автора, задачу,
закрепленную версию или ее темы. Равная версия с другим результатом отклоняется.
При повторе подтверждения чтения сохраняется самый ранний факт для этой редакции.
Для отказов сохраняются координаты в Kafka и код причины, без тела события и ключа.

`learning_task_outcomes` хранит историю оцененных попыток. Попытка без отметки
независимости остается в истории, но не дает самостоятельного свидетельства.
Представление `learning_independent_task_evidence` ограничивает вес единицей на
пару учащийся/задача, включая повторы по разным версиям. При нескольких
отмеченных попытках используется самая ранняя оценка, а не лучший результат.

Пачка до 32 сообщений записывается в одной транзакции. Offset подтверждается
после commit PostgreSQL. Если повтор не укладывается в 20 секунд, воркер закрывает
клиент и вступает в группу заново с подтвержденных offset. При потере offset
воркер останавливается: автоматического прыжка через потерянные данные нет.

## Запуск

Примени миграции и включи `RECOMMENDATIONS_LEARNING_EVIDENCE_ENABLED=true`.
Воркер работает в группе `recommendations-learning-evidence-v1` с
`KAFKA_BOOTSTRAP_SERVERS`. Если Content использует другое имя топика, задай
то же `KAFKA_CONTENT_LEARNING_TOPIC` в обоих сервисах.

Для production нужны `KAFKA_TLS_ENABLED=true` и SASL либо клиентский сертификат.
Права на запись выдаются только владельцу потока, на чтение и работу в группе
`recommendations-learning-evidence-v1` - только Recommendations. Не включай
поток на общем брокере без этих ограничений.
Оценки не передаются в AI-провайдер. Обновление модели навыков выполняется
отдельно; прием событий сам по себе не выставляет уровень знания.

## Проверки

Примени миграции на отдельную БД с суффиксом `_test`. Для проверки
Kafka укажи отдельный брокер с заранее созданными двумя топиками.

```sh
make evidence-ctest
go test ./internal/consumer -run '^$' -bench BenchmarkPostgresEvidenceWrites -benchmem
```

Тесты используют `LEARNING_EVIDENCE_TEST_DSN` и,
для проверки offset, `LEARNING_EVIDENCE_TEST_KAFKA_BROKERS`.
